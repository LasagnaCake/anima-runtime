Transfer Semantics

Transfer Semantics is the nature if how a given value is passed around.

In Breve, how a value gets passed around is defined at assignment, not declaration. Thera are three ways to pass values around:

By copy: This creates a copy of a given value, keeping the source intact.

By ref: This simply passes a reference to the given value. The ART uses ARC (Automatic Reference Counting) for managing references, so there's no need to worry about memory management.

By move: The default way values get passed around, when not specified. This moves the value from the source to the destination, and clears the source of its reference.

With some exceptions, all values in breve are, by default, passed by move.

Note

All constants are copied.

Prefix increment and decrement result in a reference to the operated value.

Postfix increment and decrement result in a copy to the original value.

For example:

var1 := "This is a string!"

// var1 is now empty (would read void)
var2 := var1

// var3 holds a copy of var2, so var2 can be modified
var3 := copy var2

// var1 holds a reference to var2, so any changes in var2 will be reflected here
var1 = ref var2

Default Variable Behaviour

For variables, its default transfer semantic can be changed.

By prepending the appropriate attribute at declaration ( @ByCopy, @ByRef, or @ByMove ), you can change how the variable passes its value around.

This only affects how the variable sends its value, not how it recieves.

This behaviour gets overridden by the transfer operators.
